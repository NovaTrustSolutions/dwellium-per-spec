## Why this matters

The owner's stated requirement for the Audit Log is "all the logins, log outs,
all the locations". Today the backend stores raw IPs only — zero geo code
exists anywhere in the repo (`grep -rn "geoip\|geolocation" src/` is empty) —
so the widget's "IP / Location" column can only ever show IPs. Separately, who
may READ the audit API is hardcoded; granting a new viewer (owner has two more
accounts pending) requires a code change + redeploy. After this plan:
`GET /api/dwellium/audit` entries carry a best-effort `location` string
(e.g. "Brooklyn, New York, US"), and the viewer set is controlled by a Cloud
Run env var (`AUDIT_LOG_VIEWER_EMAILS`) instead of code.

## Approach (decided — do not redesign)

- **Geo**: new `src/services/ipGeoService.ts`. Private/loopback IPs
  (10.*, 172.16-31.*, 192.168.*, 127.*, ::1, fc00::/7) short-circuit to
  `"local network"`. Public IPs resolve via `http://ip-api.com/json/{ip}?fields=status,country,regionName,city`
  (free, no key; note its 45 req/min limit) behind an in-memory Map cache
  (key: ip, TTL 24 h, max 5 000 entries — evict oldest). Lookup is
  best-effort with a 1500 ms timeout: on any failure return `null` and cache
  the null for 10 min (negative cache). NEVER throw. NEVER block the response:
  enrich with `Promise.allSettled` over the UNIQUE IPs of the page being
  returned.
- **Allowlist**: env `AUDIT_LOG_VIEWER_EMAILS` (CSV, lowercase). Semantics:
  a requester whose email is in the list may read the FULL audit trail
  regardless of role (the widget's use case); existing role-based rules remain
  unchanged (additive grant, not a restriction). Default when unset: empty
  list — behavior identical to today.

## Steps

### Step 1: Create `src/services/ipGeoService.ts`

Export `async function resolveLocations(ips: string[]): Promise<Map<string, string | null>>`
implementing the Approach block (private-IP short-circuit, cache, ip-api.com,
timeout via `AbortSignal.timeout(1500)`, negative caching, never throws).
Also export `function isPrivateIp(ip: string): boolean` for tests.

**Verify**: `npx tsc --noEmit` → exit 0.

### Step 2: Enrich the audit read responses in `auditRoutes.ts`

In each handler that returns `entries` (the main list the widget consumes, and
the search/global variants if they share a response builder), before `res.json`:
collect unique `ipAddress` values → `await resolveLocations(unique)` → attach
`location: map.get(e.ipAddress) ?? null` to each entry. Add ONLY the new field;
do not rename or remove anything.

**Verify**: `npx tsc --noEmit` → exit 0; `npm test` → pre-existing suites still green.

### Step 3: Add the env allowlist grant

Top of `auditRoutes.ts`: `const viewerEmails = () => csv(process.env.AUDIT_LOG_VIEWER_EMAILS);`
(copy the `csv` helper from `googleIdentityService.ts` or import it if exported).
Where the full-trail read is currently role-gated, extend the check:
`const isViewer = viewerEmails().includes((req.user?.email ?? '').toLowerCase());`
→ allow when `isViewer || <existing role check>`. Touch nothing about the
own-trail path.

**Verify**: `npx tsc --noEmit` → exit 0.

### Step 4: Integration tests — `tests/integration/auditGeoAllowlist.test.ts`

Model on the plan-024 specs. Cases:

1. `isPrivateIp` truth table (10.x, 192.168.x, 127.0.0.1, ::1, 8.8.8.8→false).
2. Entries with private IPs get `location: "local network"` WITHOUT any network
   call (mock/stub global fetch and assert it was not called).
3. Public-IP path: stub `fetch` to return a canned ip-api payload → entry gets
   "City, Region, Country"; stub a fetch rejection → `location: null` and the
   response still returns 200 with entries.
4. Allowlist: with `AUDIT_LOG_VIEWER_EMAILS=viewer@test.com`, a non-privileged
   user with that email reads the full trail (200 + other users' rows); the
   same user WITHOUT the env (unset it) gets only the pre-existing own-trail
   behavior; an email NOT in the list is unchanged.
5. Response-shape guard: every entry still has the original fields
   (id/userId/action/ipAddress/createdAt).

**Verify**: `npm run test:integration` → all pass, including the new file.
