# Plan 044: UI review — top improvements, with the reasoning behind each pick

> **How this was done (2026-08-16):** local dev build (`react-router dev`, static-API mode) at 1440×900 and 390×844, entered through the app's own offline session restore (`dwellium-auth-token=static-…` — no credentials typed), driven by Playwright; every pinned widget + ⌘K + Settings + System Health opened and screenshotted; source read where the screenshot raised a question. Screenshots: `scratchpad/shots/*.png` (session-local); the two live ARA screenshots Ilya sent today are also inputs.
> Not reviewed live: Holocron OS / Fluid OS layouts, tenant portal, backend-dependent data views (backend was offline in the harness).

## Status
- **Priority**: P1 (items 1–5), P2 (6–9)
- **Effort**: S–M each; nothing here needs a redesign — every fix reuses an existing token, store, or setting
- **Category**: UX / visual consistency / IA
- **Depends on**: none

## Principle used to choose solutions

Same rule as the codebase's ponytail ladder: prefer the fix that (a) removes a contradiction over one that adds a feature, (b) lives in an existing token/store/default over new UI, (c) is a one-line default change when a one-line change removes the problem for new users while keeping the feature for power users. Each item below says what the alternative was and why it lost.

---

## 1. Two truths about connectivity on screen at once  — P1, S

**What I saw.** Bottom-left pill: green dot **SYSTEM ONLINE**. Top of the same screen: red full-width **Backend connection failed … "Do you want to connect?"**. Both persist together on every screen. The banner copy also says "or set `VITE_API_URL`" — a build-time env var shown to an end user.

**Solution.** Bind the footer pill to `backendStatusStore` (the banner's source) so both read the same state (`Live · Reconnecting · Offline`), and rewrite the banner in product language: *"Live data paused — working from your last sync."* + `Reconnect`. Keep the dev hint behind `import.meta.env.DEV`.

**Why this one.** Contradictory status is the fastest way to make users distrust *every* indicator. Alternatives: (i) remove the footer pill — loses a useful ambient signal; (ii) restyle the banner — doesn't fix the contradiction. Binding to the existing store is ~10 lines and makes the two components incapable of disagreeing.

## 2. Windows vanish and an empty half-screen "ghost region" appears when you open a second widget  — P1, S

**What I saw.** With three windows open (Honcho, ARA, Strata), opening Scribe snapped it into the left half; the previous three disappeared from view and the right half became an empty outlined tab strip. Same for Inbox Zero, Task Board, Settings, System Health. Root: `LayoutContext.tsx` `DEFAULT_SETTINGS` = `regionsEnabled: true, regionLayout: 'halves-h'` — auto-region-snap is on for everyone.

**Solution.** Default `regionLayout: 'none'` (regions stay available in Settings and via drag-to-region). Windows open centered/cascaded like the Strata `COMPONENT_DEFAULT_SIZES` path already does.

**Why this one.** A property manager is not a tiling-WM user; the halves layout was built for a power workflow (Option-α tab groups). A one-line default change keeps every feature and removes the surprise for the first-run path. Alternative — "explain the regions with an onboarding tip" — adds UI to justify a default nobody asked for.

## 3. Sticky tooltips  — P1, S

**What I saw.** In 6 of 10 screenshots a black tooltip ("Scribe", "Task Board", "System Health (Middle-click to close)") is frozen mid-screen after clicking a sidebar item — over the Scribe "Folder ingestion" card, over the Task Board columns.

**Solution.** Hide the sidebar tooltip on `pointerdown`/click and on `pointerleave` (it currently survives the click because the hovered element unmounts/re-renders while the tooltip state stays). Add a 300 ms show-delay while there.

**Why this one.** It's the most visible defect per pixel and it's a state bug, not a design choice — the fix is where the tooltip state is set, no restyle. Alternative — switch to native `title` — loses the styled tooltip the design wants and still shows the same text.

## 4. Every widget speaks its own colour language  — P1, M

**What I saw.** Primary buttons: Scribe **amber**, Inbox Zero **amber** Retry + **blue** Search, System Health **blue** Add key, Task Board **blue** AI-file, ARA **violet**, Strata title in **lime gradient**, sidebar/theme accent **cyan-blue**. Evidence in source: **84 of 87** widget CSS files contain hardcoded hex colours (top: `TaskBoard.css` 85, `HalocronOS.css` 84, `StellaAgent.css` 82, `PersonaStudio.css` 82).

**Solution.** One `.btn-primary / .btn-secondary / .btn-danger` on the theme tokens (`--accent`, `--bg-elevated`, `--text-*`) and a sweep replacing hardcoded hex in the 8 worst files first (they hold ~60 % of the count). Keep widget-specific accents only for *semantic* colour (status/severity), never for primary actions.

**Why this one.** The 22-widget "each built separately" history explains it, and the theme system (`themes-master.css`, Customize Theme with Accent/Gradient/Success tokens in Settings) already exists — the tokens just aren't used. Token adoption fixes all 18 themes at once; a per-widget restyle would fix one theme. Alternative — "pick a widget palette per area" — institutionalises the fragmentation.

## 5. Sidebar IA: duplicates, internal names, six section headers  — P1, S

**What I saw.** *Strata* and *Task Board* appear in **Pinned** and again in **Property Management**; groups include *Universal Shell*, *Trello* (internal/borrowed names); sections: SPACES · greeting/weather · DOMAINS · WIDGETS(filter) · PINNED · PROPERTY MANAGEMENT · … with a drag handle between; group labels 10–11 px uppercase.

**Solution.** Pinned = the 5 daily drivers (already the "One Front Door" decision); hide a widget from its group while it's pinned; rename `Universal Shell` → *Work Orders* (or what it is) and `Trello` → *Boards*; collapse *Spaces* + *Domains* into one header row; body 13–14 px.

**Why this one.** The nav is the product's front door; a duplicate entry reads as "the builders lost track". Dedup is a filter, not a redesign. Alternative — a full nav re-org — needs a decision Ilya hasn't made yet (which 5 pinned was already a gate).

## 6. ARA console: unlabeled icon row + gender toggle in the composer + intro video every session  — P2, S

**What I saw.** Composer row: 8 icon-only buttons (mic, speaker, sparkle, mask, person, sliders, share) plus a prominent **♀ Female / ♂ Male** segmented control; no visible labels. The 21 MB `ara-intro.mp4` plays on every session (`sessionStorage` key `dwellium-ara-intro-played` is cleared on login/logout — `UserContext.tsx:328,369`).

**Solution.** `aria-label` + delayed tooltip on each icon; move voice gender into the existing Settings drawer (it's a preference, not a per-message action); make the intro **once per user** (persist "seen" in the per-user store) with the Skip kept.

**Why this one.** ARA is the daily driver — every session pays 21 MB + a Skip click before the first message. Persisting "seen" is a key move from session→user store that already exists for other prefs. Alternative — remove the intro — throws away an asset Ilya chose.

## 7. Login is four steps  — P2, S

**What I saw.** *Click to Login* splash → access password → pick account → email + password. The splash exists only to satisfy video-autoplay policy.

**Solution.** Splash click focuses the gate field directly (already the case) → then a **single** email + password form (skip the account picker; the picker only made sense for passwordless quick-login, which `3530a73` removed). Land this together with plan 014 (credentials off the client).

**Why this one.** Each step is a place to bounce; the picker's reason to exist is gone. Alternative — Google-only login — is already wired but gated on Ilya's OAuth publishing decision (plan 032).

## 8. Narrow viewports are half-broken  — P2, M (or S if declared desktop-only)

**What I saw.** At 390 px: sidebar stays a fixed 240 px column, the red banner wraps one word per line down half the screen, the FAB overlaps the "No active thread" pill; the desktop is unusable.

**Solution.** Either (a) `@media (max-width: 768px)`: sidebar → icon rail/drawer, banner `flex-wrap`, hide FAB when the thread pill is visible; or (b) explicitly declare desktop-only with a friendly "best on a laptop — here's the tenant portal" interstitial.

**Why this one.** Half-broken is worse than either choice. If phones aren't a target for the manager console (the tenant portal is the mobile surface), (b) is one screen and honest; if they are, (a) is the minimum. Ilya's call which — flagged, not decided here.

## 9. First screen after login is Honcho's empty memory list  — P2, S

**What I saw.** New session lands on **Honcho + Hermes — "No memories yet"** (memory tab of an agent-ops panel) plus the yellow "10 AI services need attention" toast.

**Solution.** Default stack = **ARA** (persona picker visible) + **Strata Overview**; keep System Health reachable from the toast.

**Why this one.** First impression should be the thing the user came to do; Honcho is infrastructure. The default-stack mechanism (`dwellium:default-stack:v1`) already exists — this is a content change.
